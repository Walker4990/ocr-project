# 추가할 작업 (7개)

1. OpenAPI 기반 타입 동기화
   - FastAPI OpenAPI 스키마에서 openapi-typescript로 프론트 타입을 생성하는 스크립트와 CI 검사
   - 스키마 변경 시 생성 타입이 최신이 아니면 CI 실패
   - 의존: 19(API 엔드포인트), 4(프론트 골격). 프론트 화면 태스크(23, 24)가 이 타입을 쓰도록 연결

2. Playwright E2E 테스트
   - 업로드 → 처리 완료 → 검수 화면에서 필드 수정 → 승인 → 엑셀 내보내기 전체 흐름
   - 합성 샘플 문서만 사용, CI에서 실행 가능한 구성
   - 의존: 24, 25

3. 규칙 vs 규칙+LLM 벤치마크 비교
   - 기존 벤치마크(14)를 확장해 추출 방식별 필드 정확도, 검증 경고 건수, 처리시간, LLM 호출 비용(토큰 기준)을 비교
   - LLM 단가는 코드에 하드코딩하지 말고 설정값으로 두고 측정 시점의 공식 단가를 확인해 기록
   - 결과를 benchmarks/results.md에 CPU 기본 / GPU 옵션 / 규칙+LLM 비교 표로 추가
   - 의존: 14, 22

4. 보안 및 개인정보 보호 적용
   - 업로드 형식(png, jpg, pdf)/크기 제한과 매직 바이트 검사
   - 보관 기간 정책: 기간이 지난 파일과 데이터 자동 삭제 작업(arq 주기 작업), 기간은 설정으로 조정
   - 엔드포인트별 레이트 리밋, CORS 화이트리스트
   - 로그에 문서 본문/개인정보가 남지 않는지 점검하는 테스트
   - 의존: 19, 20

5. 라이브 데모 배포와 샘플 체험
   - CPU 기반 데모 배포 구성(배포 대상을 먼저 제안하고 확인받은 뒤 진행)
   - 샘플 문서 원클릭 체험 기능, LLM은 샘플 문서에만 허용
   - 모델 가중치 캐시로 콜드 스타트 시간을 줄이는 구성
   - 의존: 5, 24, 25, 4번 보안 항목 태스크, 새 벤치마크 비교 태스크

6. README와 아키텍처 문서
   - 아키텍처 다이어그램, 실행 방법(docker compose up), 환경변수 설명, 벤치마크 표(측정값만), 데모 GIF
   - 처음 보는 사람이 5분 안에 로컬 실행과 데모 체험이 가능해야 한다
   - 한계(촬영 문서 정확도 하락, 양식에 따른 표 인식 실패)를 명시
   - 의존: 라이브 데모 배포 태스크, 벤치마크 비교 태스크

7. 숨고 프로필용 케이스 스터디
   - 문제, 접근, 정확도 수치, 처리시간, 운영 비용, 확장 가능 영역(다른 문서 유형, 다른 ERP/회계 연동) 순서
   - 모든 수치는 benchmarks/ 측정 결과를 근거로 한다
   - 의존: README 태스크
